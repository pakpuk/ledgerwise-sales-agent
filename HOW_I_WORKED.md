## 1. Tools for each step, and why

| Step | Tool | Why I chose it |
|---|---|---|
| **Research: find companies** | **Tavily** search API + **Gemini** | Tavily returns page text with each result, so the LLM can pick candidate brands *and* the code can check each quote against real text. 16 queries aimed at recent triggers (finance/ops hiring, funding, new channels). |
| **Research: collect facts** | `fetch` + a 30-line HTML-to-text helper, then Gemini extracts facts | Marketing pages and job posts don't need a scraping service. **Every fact's quote is checked in code against the saved page; facts that don't match are dropped, never stored.** |
| **Qualify** | Gemini (structured JSON, validated with Zod) gives a verdict per criterion and cites a `fact_id`; **the score is computed in code** | The score stays explainable and reproducible. A verdict that cites no real fact is downgraded to "unknown". Each reason is shown with its quote and source link. |
| **Write emails** | Gemini + code validators | Rules are enforced in code, not only in the prompt: no prices, every claim linked to a fact and supported by its quote, ≤120 words, opt-out line added by code. One rewrite with the problems listed, then "Needs you". |
| **Replies** | Stop check in code (no LLM) → Gemini classifies → **routing in code** | The risky paths never depend on the model: stop/unsubscribe, the honest "are you a bot?" answer and pricing all use fixed, approved texts. Questions are answered only from a small knowledge base; anything unsure, hostile, legal or non-English goes to a human. |
| **Book calls** | **Cal.com API v2** | Real free slots (9:00–17:00 in the prospect's timezone) and real bookings. An idempotency key (thread + slot) prevents double bookings. Simulated slots are the labelled fallback. |
| **Platform** | Next.js 16 + TypeScript, Tailwind, Zod, Drizzle + Neon Postgres, Vitest | Fast to build and type-safe end to end. Clean architecture kept light: `domain` (pure rules), `application` (one file per use case + ports), `infrastructure` (adapters), `app` (UI). |
| **Mail** | Sandbox adapter | The case must not email real companies; prospect replies are simulated from the Inbox. |
| **Hosting** | **Vercel** + Neon (Vercel integration) | Native Next.js hosting; free tiers. |
| **AI coding tool** | **Claude Code** | Built in checkpoints, each ending with typecheck + tests + a log entry + a commit. |

**Tried and dropped**
- **shadcn/ui CLI:** skipped to save setup time on Next 16 / Tailwind 4; I wrote 5 small components in the same style instead.
- **Gemini 2.5 models:** retired for new API users (HTTP 404); switched to Gemini 3.5.
- **`gemini-3.5-flash` as the "smart" model:** hit the free-quota limit mid-run, so `gemini-3.5-flash-lite` now runs both tiers. The provider sits behind an `LlmPort`; an Anthropic adapter also exists.

## 2. The plan, and how it changed

**Initial plan:** six checkpoints, MVP first: (1) architecture, schema, business-rule guards, login, screens; (2) research + qualification; (3) email drafts + review queue + a single send path; (4) reply agent + inbox; (5) booking + calls; (6) evals, costs, docs, deploy.

**What changed**
1. **Brief corrections:** there is no price list, so *any* price wording is now blocked and pricing questions get a fixed "we cover that on a call" answer with slots.
2. **Booking moved earlier**, because "Tuesday works" can't be tested without it.
3. **Built against fake adapters first, then a live pass.** The API keys arrived late, so checkpoints 1–6 were built and tested with fakes. The live pass (real Gemini, Tavily, Neon, Cal.com) found most of the real bugs (section 4). *Lesson: connect real services on day one.*
4. **Model plan changed twice:** stale model names, then a quota limit (fast model for both tiers).
5. **Scope frozen at the end:** Cal.com setup, graceful failure, final eval, secret scan, deploy, documentation. No new features.

## 3. Rules and context given to the AI coding tool

- **`claude.md` (project rules):** the client and its customer profile; the five business rules, to be **enforced in code, never only in prompts**; scraped pages and prospect replies treated as untrusted input (delimited, never followed as instructions, only Zod-validated output accepted); sandbox mail only; one single function that sends anything; models chosen from env; idempotent booking; strict TypeScript, Zod at every boundary, a unit test for every rule; log every mistake and correction in `LOG.md`; never commit secrets.
- **Session instructions:** time budget and checkpoint workflow; the technology choices; the customer profile, triggers and email tone (<120 words, one real fact, one soft ask, opt-out line, no price); "invent a minimal knowledge base and list it as *to confirm with the client*" (`docs/ASSUMPTIONS.md`).
- **Mid-course decisions I made:** no price list; don't pause between checkpoints; use the fast model only; final freeze list, including **"do not loosen the qualification rules to inflate numbers."**

## 4. Where the AI got it wrong, and how I noticed

**Truthfulness and business rules**
| Mistake | How it was noticed | Fix |
|---|---|---|
| Assumed an approved **price list** existed | I corrected it | Any price wording blocked; fixed pricing answer |
| **A draft made a false claim:** "Blenders is hiring for fulfillment and operations roles", but its source was a UX job ad. The check only verified that the fact existed, not that it supported the claim | Reading the first real drafts | Facts now store the verified quote itself; new code check that a claim's key words appear in its quote; the real case is a regression test |
| **Scoring too generous:** "US e-commerce, everything else unknown" scored 61 (qualified); a 2020 funding round and a UX hire were accepted as reasons to reach out now | Reviewing live scores | "Unknown" credit 40% → 25%; triggers must be recent and finance/ops related |
| "Stop spamming me" not caught as stop; "CAN-SPAM" not seen as legal | Writing the eval cases | Rules + tests |
| When the AI failed, a **bot question was escalated instead of answered honestly** | First live eval | Shared safe fallback that always answers honestly |
| Some failures (AI quota, calendar outage) **crashed instead of handing over to a human** | Final graceful-failure check | One guard: thread goes to "Needs you" with the reason, nothing is sent (2 tests) |

**Integration and deployment**
| Mistake | How it was noticed | Fix |
|---|---|---|
| Stale Gemini model names (retired) | Every LLM call failed in the first live eval | Listed the models available to the key, switched |
| **Cal.com offered 3:00 AM slots** (schedule set in a European timezone) | First live availability call | Only offer 9:00–17:00 in the prospect's timezone |
| **Cal.com rejected every booking:** prospects have sandbox addresses that can't receive mail | Live booking test | Bookings use a real team inbox (`CAL_BOOKING_EMAIL`); a failed booking now goes to a human instead of telling the prospect "that time was taken" |
| Vercel deploy had **no env vars** (login impossible) and **Deployment Protection** blocked reviewers | Login failed on the live site; logs showed `APP_PASSWORD is not set` | Set the variables, made the deployment public (the app keeps its own login), rebuilt |
| A Vercel "redeploy" reused the old environment | Warning banner still visible after the redeploy | Fresh build from GitHub |
| API keys were saved into `.env.example` (a tracked file), twice | The AI noticed the file had changed and refused to stage it | Keys moved to the gitignored `.env.local`; a scan of the full git history is clean |

**Process slips:** a page was prerendered as static (would have shown stale data); a test file was saved in the wrong encoding; `drizzle-kit push --force` was run before checking the database contents (checked right after: nothing was lost); the cost report showed a misleading "$0" for unpriced models.

**Known gap, not fixed (scope frozen):** when a company's revenue or headcount is unknown it doesn't count against it, so a few large brands (e.g. Vuori, Shapermint, OOFOS) qualified. A human should check size on the Companies page.

## 5. How I checked that the agent is right

- **93 automated tests** cover every business rule and use case, including the real failures above as regression tests.
- **Reply eval** (`npm run eval`): 17 realistic replies (stop ×4, bot question, pricing, objection, knowledge-base question, wants a call, "Tuesday works" ×2, maybe later, hostile, legal, non-English, prompt injection, out-of-office). It runs the real reply agent with the real LLM and checks **what was actually sent**: no price, no reply after a stop, domain suppressed, honest bot answer, nothing sent while escalating.

| Run | Routing | Rule violations | Bookings |
|---|---|---|---|
| Final (flash-lite, both tiers) | **17/17** | **0** | **2/2** |
| With `gemini-3.5-flash` as smart model (2 runs) | 17/17, 17/17 | 0, 0 | 2/2, 2/2 |
| No AI at all (rules only) | 12/17 (every miss went to a human) | 0 | 0/2 |

- **Research:** 121 facts stored, each quote verified in code against the saved page. 13 of 21 companies qualified.
- **Drafts:** all 15 re-checked against the final rules: 11 pass, 4 flagged "Needs you" (1 unsupported claim, 3 dollar amounts from the prospect's own news that the price rule blocks on purpose). I read about 7 by hand: grounded in their sources, with minor wording artefacts.
- **Calendar:** real Cal.com availability verified; one live booking created and confirmed (the slot disappeared from availability afterwards).

**Limits, stated plainly:** 17 test replies and 2 booking cases are a small sample. They show each route works, not a measured error rate. Email quality was judged by hand on a handful of drafts.

## 6. Cost to run, and next steps

**Cost** (measured in tokens: the calls ran on a free Gemini quota and Gemini 3.5 prices weren't on file)
- Research + qualify + draft: **~12.5k tokens per lead** (262k tokens over 121 calls for 21 companies; fact extraction is the largest share).
- Replies: **~490 tokens per reply**.
- Infrastructure: Vercel, Neon, Tavily and Cal.com free tiers. At flash-lite-class pricing this is well under one cent per lead; I would confirm against the official price sheet before quoting a figure.

**With more time, I would:**
1. Reach 30+ companies and add a **company-size check**, so unknown revenue doesn't let large brands qualify.
2. Grow the eval to **100+ real-world replies** and a human-rated set of 30 drafts, tracked per prompt version.
3. Polish the drafts (smoother wording, use the founder's name whenever a source names them).
4. Add follow-up emails and a daily "Needs you" digest for the sales team.
5. Improve the UI further: richer company detail pages, filters and bulk review.

## 2. The plan, and how it changed

**Original plan** (given at the start, about 2 hours): 6 checkpoints. (1) layers, schema, guards, login, empty screens; (2) research + qualify + Companies; (3) draft + Review queue + single send path; (4) reply agent + Inbox; (5) booking + Calls; (6) evals, costs, README, deploy. MVP of everything, clean architecture but light.

**How it changed:**
- **The brief files were missed at first.** `claude.md` / `case_study.md` sit at the repo root, not at `CLAUDE.md` / `docs/CASE_STUDY.md`, so CP1 was built from the chat prompt alone. After the brief arrived I restructured to its layout (`domain/rules`, `application/ports`, `use-cases`, `prompts`, `container.ts`).
- **Corrected by me:** there is no price list. The AI had built a price guard with an "allowed prices" list; now *any* price wording is blocked and pricing questions get a fixed "we cover that on a call" answer.
- **Booking was pulled forward** into the reply checkpoint, because "Tuesday works" can't be tested without it.
- **Everything was first built against fake ports** because no keys were available for the first ~1.5 h. The live pass then found the real bugs (section 4). Lesson: get the keys in at the start next time.
- **Model plan changed twice:** stale model names → `gemini-3.5-flash-lite` / `gemini-3.5-flash` → flash-lite for both (free-quota limit; my decision).
- **Scope frozen** at the end: Cal.com setup, graceful failure, final eval, secret scan, build, push, this document. No new features.

## 3. Rules and context given to the AI coding tool

## 5. How the agent's answers were checked (with numbers)

- **Unit and use-case tests:** 93 tests on every business rule and use case (fake ports), including the real failures above as regressions.
- **Reply eval** (`npm run eval`, 17 cases: stop x4, bot, pricing, objection, KB question, wants call, "Tuesday works" x2, maybe-later, hostile, legal, non-English, prompt injection, out-of-office). It runs the real `handleReply` with the real LLM and checks **what was actually sent**: prices, replies after a stop, domain suppression, the honest bot text, nothing sent while escalating.
  - Final run (flash-lite both tiers): **17/17 routed correctly, 0 rule violations, 2/2 bookings**, ~490 tokens per reply, 1 invalid model output fixed by the retry.
  - With `gemini-3.5-flash` as the smart model: 17/17, 0, 2/2 on **two** runs.
  - Without any LLM: **12/17**, 0 violations; every miss went to a human (the safe failure).
  - **Caveat:** 17 cases with 2 booking cases is a small sample. It shows each route works, not an error rate. It also runs against a fixed fake calendar, not Cal.com.
- **Research checks (live):** 21 companies, 51 pages, **121 facts stored, every quote verified in code against the saved page text** (failed quotes are dropped, never stored). 13/21 qualified.
- **Draft checks (live):** 15 drafts; `npm run recheck-drafts` re-ran today's rules: **11 pass, 4 flagged "Needs you"** (1 unsupported claim, 3 dollar amounts from the prospect's own news, which the price guard blocks on purpose). I read about 7 drafts by hand: grounded in their quotes, with some copy artefacts (pasted headline wording).
- **Not measured:** human-rated email quality on a larger set, classifier accuracy beyond 17 cases, a live Cal.com booking, and behaviour at higher volume.

## 6. What it costs to run, and what I'd do next

**Cost (measured in tokens, because Gemini 3.5 prices aren't on file and the calls ran on a free quota):**
- Research + qualify + draft: **~12.5k tokens per lead** (262k tokens over 121 calls for 21 companies; fact extraction is ~55% of input tokens).
- Reply handling: **~490 tokens per reply** (classification; KB answers add a second call).
- Infra: Neon free tier, Vercel hobby, Tavily free tier (~20 searches used), Cal.com free. At flash-lite-class prices this is well under a cent per lead; I'd confirm with the real price sheet before quoting a number.

**Next, with more time:**
1. Reach and pass **30+ companies** (more queries, seed lists), and add a **size check** so unknown revenue doesn't let large brands qualify (e.g. require some evidence, or penalise known large brands).
2. **Grow the eval** to 100+ replies (including real-world messy ones) and a human-rated set of 30 drafts; track the numbers per prompt version.
3. Make one **live Cal.com booking** against a test event type, then deploy to Vercel and run the eval against the deployed app.
4. Better drafts: smooth pasted headlines, use the founder's name more often (only when a fact names them).
5. Follow-up emails and a daily digest of "Needs you" items for the sales team.
